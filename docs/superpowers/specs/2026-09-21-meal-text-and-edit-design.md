## 1. 问题

记餐目前**只能拍照**：`_pick(ImageSource.camera / gallery)` 两个入口都是图片，
`analyzeMeal` 写死 `needsVision: true`。没带手机拍、或者吃完才想起来记，就没法记。

## 2. 前置阻塞：食物明细没有热量

`FoodItem` 只有 `name` + `grams`，热量宏量只存在整餐层面：

```dart
class FoodItem {
  final String name;
  final int grams;
}
```

所以**删掉一样食物，系统不知道该减多少**；改分量也不知道怎么缩放。
「编辑食物清单」必须先改数据契约。

### 新契约

```json
{"foods":[{"name":"米饭","grams":150,"kcal":174,"proteinG":4,"carbG":39,"fatG":0}],
 "kcal":整数,"proteinG":整数,"carbG":整数,"fatG":整数,"note":"一句点评"}
```

整餐值仍让 LLM 给，但**本地以明细之和为准**——否则编辑后无法重算。

LLM 只给整餐、不给明细时（老数据、模型偷懒）退回整餐值，
该餐标记为不可逐项编辑，界面如实说明而不是假装能编辑。

## 3. 文字记餐

`FitnessLlm.analyzeMealText(meal, description)`，复用同一套 system prompt
（措辞从「用户拍了一张照片」改为按输入方式切换），`needsVision: false`。

记餐页顶部三个入口：**📷 拍照 · 🖼 相册 · ✍️ 说两句**。

---

## 4. 编辑食物清单

- 三餐 `CreamPill` 上已记录的（✅）点击 → **带着已存数据进编辑页**
- 清单每行：食物名 + 克数 + 该项热量，右侧删除
- **改克数 → 该项按比例线性缩放，整餐实时重算**（纯本地，零延迟）
- **删除 → 直接减掉**（纯本地，零延迟）

### 新增食物：复用文字分析，不加新 LLM 入口

新增一样食物没有基准数值。做法是复用 §3 的文字路径：
用户输入「米饭 150g」→ 调 `analyzeMealText` → 取 `foods[0]`。

不引入第三个 LLM 入口，也不要求爸爸手填热量（他不知道）。

## 6. 两个刻意的取舍

1. **整餐热量以明细之和为准**，而非 LLM 给的整餐值。
   好处是编辑逻辑自洽；代价是 LLM 明细之和与它自己给的整餐值不一致时，
   显示的是明细之和。
2. **改克数按线性比例缩放**。米饭 150g→200g 热量 ×1.33 够用；
   对「一整只鸡 vs 半只鸡」这类非线性情况不精确。

## 8. 测试策略

- `FoodItem` 解析：带明细 / 不带明细 / 明细不全
- 明细之和 vs 整餐值的取舍逻辑（纯函数）
- 克数缩放：比例正确、四舍五入、克数为 0 的边界
- 删除后整餐重算
- 文字分析走 `needsVision: false`，prompt 措辞随输入方式切换
- 编辑入口：已记录的餐能把数据载回页面
- widget 测试照例做变异验证
